引力波引擎

一条内容进来，
三步被捕获。

01丢进去

随手投入，不做选择

链接、文档、一段想法，直接丢。你不需要先想好"它属于哪里"。

02引力打分

标题 ×3，正文加权

引擎拿 22 类关键词做引力测算：标题命中权重最高，正文命中逐词累加，产出每一类的得分。

03归入书架

够强就归档，不够就商量

得分越过阈值的类型直接收编；模糊的进收集箱，附上引力建议，由你一键裁决。

肆
双层分类流水线

客户端先分一层，
服务端再核一层。

第一层 · 客户端

喵藏 Client 粗分

桌面的猫先看一眼：标题、摘要、大纲、正文分段加权，把内容放进对应分类文件夹；实在拿不准，丢进「收件箱」兜底。

→
第二层 · 服务端

引力波复核

服务端重新独立打分，与客户端的意见对照：一致就归档，分歧交给你，没有意见就尊重客户端。

两层一致 → 直接归档零打扰，内容悄悄落进书里。
两层分歧 → 待你裁决收集箱同时给出「引力建议」与「客户端放置」。
客户端兜底 → 收集箱「收件箱」视为未分类，等服务端引力建议。
引力无意见 → 尊重客户端第二层不越权，第一层说了算。

书的形态

每本书，
都有二级目录。

归档不是扔进文件夹了事——每条内容会按目录规则挂进书的章节。 你也随时可以把任何内容手动指定到任何一本书的任何一节。

与喵藏客户端联动

你的书，
本地与服务端同构。

01本地即全部

纯 Markdown 书库

客户端把整座书库落在本地磁盘：分类文件夹 + 日期命名 + front-matter，任何编辑器都能打开。

02Git 双向同步

push 即送达

客户端与服务端文件结构完全一致，一条 git push 就完成同步，每次变更都有提交记录可回溯。

03双向认领

谁新增，谁补录

服务端采集的内容落盘并提交，客户端 rescan 一键收编；客户端写的笔记 push 上来，服务端自动补录进库。
