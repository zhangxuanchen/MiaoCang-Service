# 喵藏 · 产品设计理念与改进方案

> 定位：一款解决「知识爆炸」的 AI 知识整理与学习产品。
> 核心隐喻：**内容引力波**——新知识像引力波一样被喵捕捉、吸收、沉淀，最终变成「书」与「卡片」。

---

## 一、设计理念（产品宪法）

**要解决的问题**：各种公众号、书籍都想看，但应接不暇——收藏了不等于读了，读了不等于懂了，懂了不等于会用。

**核心理念**：新知识到来 → 引力波抓取 → 进入统一的知识处理工作流：

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│ 引力波抓取 │ →  │ ① 把书读厚 │ →  │ ② 把书读薄 │ →  │ ③ 学透   │
│ 收藏/URL/ │    │ 逐篇精读   │    │ 卡片关联   │    │ 苏格拉底  │
│ 文章/书摘  │    │ 理解卡片   │    │ 记忆成书   │    │ +学习卡片 │
└─────────┘    └─────────┘    └─────────┘    └─────────┘
```

1. **把书读厚**：喵逐篇精读每篇文章（有链接的点开链接读），一篇拆出多张**理解卡片**——不是摘抄，是「读完后的理解」。
2. **把书读薄**：理解卡片相互关联、分类分层，结构化排序后**记忆成书**（一本本二级主题书）；书的详情随时关联回「厚」的知识点（卡片 → 原文），厚薄互为索引。
3. **苏格拉底反问 + MIT 学习法**：喵用反问帮主人检验理解（追问、纠偏、举一反三），并把值得记住的内容提炼成**学习卡片**（正面问题/背面答案），供碎片时间主动回忆。

**两大产物**：
- **书**（系统学习）：碎片整理出的二级主题书，帮人建立结构化知识体系。
- **学习卡片**（碎片学习）：提取感兴趣的内容，帮人在碎片时间高效复习。

**产品判断标准**：每一条知识从「抓取」到「学透」有完整、可见、可追溯的旅程；用户随时知道「这条知识走到哪一步了」。

**工程宪法**（与产品理念同等级的硬约束，详见第六节）：工作流中**每个节点都是一个完整的 AgentHarness**——必须有目标、入参标准、出参标准、生成物合格验证标准；**生成物合格才能进下一阶段**；多层防护无限循环；用**五区上下文记忆法**管理每个 Agent 的上下文；Agent 执行完即销毁、上下文清除干净，不污染下一次运行；运行中捕获的用户偏好沉淀为**喵的专属技能**。

## 二、现状盘点：理念 ↔ 现有实现映射

| 理念环节 | 现有实现 | 状态 |
|---|---|---|
| 引力波抓取 | 投入内容（URL/文本，Jsoup 抓取 + AI 抽取入库） | ✅ 已有，缺「全链路状态可视化」 |
| 把书读厚 | 喵的阅读·阶段一：逐篇精读 → 理解卡片（md 内 `📇` 卡片行） | ✅ 已有（真实模型 21 篇 → 57 卡），卡片仅存在于 md 文本，**未结构化、不可单独浏览复习** |
| 把书读薄 | 喵的阅读·阶段二：卡片归纳成二级主题书（`reading/*.md`） | ✅ 已有；**书 → 卡片 → 原文的反向关联只在 md 里，界面上点不动** |
| 学透（苏格拉底 + 学习卡片） | 无 | ❌ **最大缺口**：没有主动学习/检验环节，产物只停留在「读过了」 |
| 碎片学习产物 | 无（理解卡片≠学习卡片） | ❌ 学习卡片（Q/A 主动回忆）缺失 |
| 知识关联可视化 | 四层知识图谱（猫→分类→书→内容叶子） | ✅ 已有，可承接「厚薄互链」的展示 |
| 工作流治理（AgentHarness） | 阅读流水线硬编码在 ReadingService：无契约四件套、无门禁校验、无防循环、无五区上下文、跨运行状态残留风险 | ❌ **架构缺口**：P0 按第六节规格重构 |

**结论**：读厚/读薄两环骨架已成，下一步的杠杆是——① 卡片结构化；② 补上「学透」环节（学习卡片 + 苏格拉底会话）；③ 把三个产物在同一界面里串成学习旅程；④ 工作流按 AgentHarness 规格治理（契约门禁 + 五区 + 销毁，P0）。

## 三、改进设计

### 3.1 数据模型：把卡片从 md 升级为一等公民

新增两张 H2 表（沿用现有 JPA 模式，schema 由 JPA 自动建）：

```
UnderstandingCard（理解卡片，「读厚」产物）
  id, contentId（出处内容）, topic, point, bookOutlineMd（所属书/主题回填）, createdAt

LearnCard（学习卡片，「学透」产物）
  id, understandingCardId（来源，可空）, bookFile（来源书，可空）
  front（正面提问）, back（背面答案）, kind（recall 主动回忆 / feynman 费曼复述 / socratic 苏格拉底问答）
  ease(2.5), interval(0), due(当天), reviews(0), createdAt
```

- `reading/*.md` 保持不变（人的可读产物），但生成时同步落 UnderstandingCard 行——**md 给人读，卡片给系统用**。
- LearnCard 复习调度用简化 SM-2：记住 → interval×ease；模糊 → interval 不变；忘记 → 归 1 天。

### 3.2 「学透」环节（新增核心）

**(a) 学习卡片生成**（并入喵的阅读流水线第三阶段）：

```
精读（读厚）→ 归纳成书（读薄）→ 出学习卡片（学透）
```

- 阶段三 Prompt：基于理解卡片 + 书的二级主题，每本书出 **≤ 5 张**学习卡片（宁少勿多）：
  - `recall`：正面 = 一个值得回答的问题；背面 = 基于理解的答案（不是原文抄写）
  - `feynman`：正面 = 「用你自己的话解释 X」；背面 = 参考讲法要点
- **防反噬规则**（头号风险对冲：稍后读类产品死于「读不动」，卡片复习不能死于「复习不动」）：
  - 每天到期卡 **≤ 10 张封顶**，超出自动顺延，永远不让复习列表变成焦虑源
  - 连续 3 次自评「忘记」的卡自动降频为周检；连续 3 次「记住」的卡自动休眠（不再到期）
  - 首页给「今日 3 分钟」轻入口（只推 3 张最高价值卡），对抗「一想到要复习 30 张就不打开」
- 卡片落 LearnCard 表 + 书的 md 末尾追加「## 学习卡片」段落（人可读）。

**(b) 苏格拉底会话**（复用现有聊天管道）：

- ChatSessionService 增加 `mode=SOCRATIC` 预设：喵只提问不直接给答案——先问主人「你觉得这篇文章讲了什么」，再针对模糊处连环追问（「为什么？」「如果 X 不成立会怎样？」），最后喵给一句总结评价 + 一句掌握度评估（✅ 懂了 / 🔁 再想想）。
- **定位克制**：被连环追问是高认知负荷交互，多数用户会逃避——它是「重要知识的深度模式」（用户主动点选的可选入口），不是默认路径，也不作为主打卖点宣传。默认学习路径永远是「低摩擦的卡片复习」。
- 会话结束后喵可把暴露的薄弱点转成待复习 LearnCard（kind=socratic，front=刚才问倒主人的问题）。
- 入口：阅读页书的抽屉里「🎓 和小喵苏格拉底一下」按钮 → 跳到与该猫的会话，自动带上书的上下文。

### 3.3 产物界面：书房里的「学习中心」

把现有「喵的阅读」页升级为**三页签**（同一 hero，切换产物形态）：

| 页签 | 内容 | 对应理念 |
|---|---|---|
| 📚 书 | 现有二级主题书卡片网格（含「· N 卡」徽标） | 读薄 → 系统学习 |
| 🗂 理解卡片 | 卡片墙：topic 胶囊 + point 摘要 + 出处《…》，点开原文详情 | 读厚 → 可追溯 |
| 🎓 学习卡片 | 今日到期卡流（翻转卡：正面问题 → 点击翻面 → 自评 记住/模糊/忘记） | 学透 → 碎片学习 |

**全链路状态条**（每个内容条目一条旅程线，回应「随时知道走到哪一步」）：

```
◉ 已抓取 ── ◉ 已读懂(2卡) ── ◉ 已入书 ── ○ 待出卡 ── ○ 待复习
```

- 内容详情弹窗底部加这条旅程线，五段点亮状态来自数据（rawText 有无 / 理解卡片有无 / 归书 / LearnCard / due）。
- 点「已入书」直接跳书，点「待复习」直接进卡流。

### 3.4 知识图谱承接「厚薄互链」

- 点击书节点 → 现有抽屉升级：显示「书的结构（二级主题）+ 每主题理解卡片 + 出处内容」，实现「书的详情关联回厚的知识点」。
- 图上不新增卡片层（防节点爆炸）；卡片通过书抽屉呈现——薄在图上，厚在抽屉里。

### 3.5 引力波体验贯穿（轻量动效，不喧宾夺主）

- 投入内容成功 → toast 升级为「🌀 已被小肥的引力波捕获」+ 内容卡片从顶部飞向侧栏猫头像的一次性动画（300ms）。
- 喵的阅读生成中 → hero 显示引力波纹扩散动画（CSS，2 圈涟漪循环）+ 现有精读进度文案。
- 卡片归书完成 → 书卡片上「· N 卡」徽标 +1 时轻微弹跳。

## 四、UI 规范（延续现有视觉体系）

- **三色系统**：奶油纸底（页面）+ 白/米白卡片（panel）+ 墨黑描边元素（按钮/胶囊）；白绿主题做「学习卡片」页主色调（淡绿底 `#DFF3EC` + 绿描边 `#0F6E56`），与用户输入区呼应——学习=行动=绿。
- **卡片翻转**：学习卡用现有粗描边+硬偏移阴影语言（`--shadow-sm: 4px 4px 0 var(--ink)`），翻面 0.25s；自评三按钮：记住（绿实心）/ 模糊（黄描边）/ 忘记（红描边），宽度一致 96px。
- **字号层级**：主信息 13px / 次要 12px / 元信息 11px；页签用胶囊组（与筛选器胶囊同款：大写小标签 + 加粗深字 + 悬停绿描边）。
- **图标**：书 📚、理解卡片 🗂、学习卡片 🎓、苏格拉底 🎓+💬、引力波 🌀；SVG 图标随父字号。
- **状态点**：旅程线五段用现有红点锚点条同款语言：完成=墨黑实心、进行中=绿描边光晕、未开始=浅灰空心。

## 五、落地路线图

**P0 · 卡片结构化 + 阶段函数化（地基，~2 天）**
- UnderstandingCard 表 + 喵的阅读阶段一落库（md 照旧生成）
- 「🗂 理解卡片」页签（卡片墙 + 点开出处详情）

**P1 · 学透环节（核心价值，~2 天）**
- LearnCard 表 + learn 阶段（生成 recall/feynman 卡，每书 ≤ 5 张，契约四件套同规格）
- 此时第二个阶段执行体真实出现 → 从事实中抽出 `HarnessAgent` 接口
- 「🎓 学习卡片」页签：到期卡流（每日 ≤ 10 张封顶）+ 翻转 + 自评 + SM-2 调度 + 「今日 3 分钟」轻入口
- 书 md 末尾「## 学习卡片」段落
- learn 阶段接入 Skill 拼装 + 反馈闭环（含偏好防污染规则）

**P2 · 苏格拉底 + 旅程线（体验闭环，~2 天）**
- 会话 SOCRATIC 预设（可选深度模式，克制定位——见 3.2b）+ 书抽屉入口 + 薄弱点转卡
- 内容详情「全链路状态条」+ 阶段调用 Token 成本展示（复用现有 TokenUsage 统计）
- 引力波动效（投入捕获 / 生成涟漪 / 徽标弹跳）

**P3 · 打磨（按反馈）**
- 图谱书抽屉「厚薄互链」完整版；学习统计（连续打卡、掌握度曲线）；多喵各自的卡池隔离（现有多猫结构天然支持）
- HarnessBinding 按猫配置阶段执行体（换模型 / 换提示词模板），技能弹窗按阶段分组

## 六、工作流架构：HarnessAgent 管道（每阶段 = 一个可嵌入的 Agent）

> 理念：知识提炼工作流的**每个阶段都是一个 HarnessAgent**，可以嵌入、替换、配置；
> **Skill 辅助提炼效果 + 记录偏好**——Agent 不是一次性提示词，而是「提示词 + 技能 + 偏好」的装配体，越用越懂主人。

### 6.1 现状基础（已有 60%）

现有系统已有一套经过验证的 Skill 闭环，但目前**只用于内容提取（ExtractPipeline）一个阶段**：

| 已有设施 | 作用 |
|---|---|
| `AgentSkill`（kind=EXTRACT/PREFERENCE，按猫归属） | EXTRACT=提取规则拼进提示词；PREFERENCE=主人喜好 |
| `AgentFeedback`（action + skillCodes 归因 + consumed 标记） | 记录主人对产物的处理动作，供喵周期性总结出新 PREFERENCE 技能 |
| `usageCount` | 观察哪个 skill 真正带来价值 |

**缺的是**：喵的阅读工作流（读厚→读薄→学透）目前硬编码在 ReadingService 里，没有走 Skill 装配，也没有反馈记录——提炼效果不可积累。

### 6.2 HarnessAgent 契约

```java
/** 工作流阶段执行体：可嵌入、可替换、可装配 Skill */
public interface HarnessAgent {
    String code();                        // 阶段标识：extract / read-deep / read-thin / learn
    String name();                        // 显示名（前端阶段卡展示）
    String run(HarnessContext ctx);       // 执行，返回产物（JSON / md 文本）
}

/** 阶段运行上下文：输入 + 装配好的 Skill + 反馈回写 */
public class HarnessContext {
    Long catId;
    Object input;                         // 阶段输入：内容正文 / 卡片列表 / 书大纲
    String skillsPrompt;                  // 拼装好的技能附录（EXTRACT 规则 + PREFERENCE 偏好）
    Consumer<AgentFeedback> feedback;     // 产物被主人处理后回写反馈（带 skillCodes 归因）
}
```

- **每阶段两个实现**：`LlmHarnessAgent`（默认，内部走 MiaoMiaoAgent.chat）与 `MockHarnessAgent`（未配 AK 的模拟输出）——与现有 MiaomiaoService 双模式一致。
- **可嵌入**：阶段 ↔ 执行体的绑定默认「按猫 + 按阶段」，P3 引入 HarnessBinding 配置（`catId + stage → agentCode`），可换模型、换提示词模板，不动管道。
- **流水线编排**：ReadingService 退化为编排器——按阶段顺序执行、装配 Skill、门禁校验、传递产物、记录任务进度（现有 current 文案机制不变）。

#### 6.2.1 完整 AgentHarness 规格（硬约束：目标 / 入参标准 / 出参标准 / 验证标准）

> 每个工作流节点不是一个函数，而是一个**完整的 AgentHarness**——四件套缺一不可，生成物合格才能流转下一阶段。

```java
/** 阶段规格：一个节点 = 一份完整契约（声明式，编排器按此执行与校验） */
public class HarnessSpec {
    String goal;            // 目标：本阶段为什么存在（一句话，拼进 system prompt）
    String inputContract;   // 入参标准：输入必须满足什么才允许启动（不满足直接拒绝，不浪费调用）
    String outputContract;  // 出参标准：产物结构/格式/数量边界（模型输出的验收依据）
    QualityGate gate;       // 生成物合格验证标准：一组可编程断言
}
@FunctionalInterface
public interface QualityGate { GateResult check(Object output, HarnessContext ctx); }
```

**各阶段契约示例**（落地时逐阶段填实）：

| 阶段 | goal（目标） | inputContract（入参） | outputContract（出参） | gate（验证断言） |
|---|---|---|---|---|
| read-deep 读厚 | 逐篇精读产出理解卡片 | 正文非空；URL 类必须已抓取正文 | JSON 数组，每篇 1~3 卡，每卡 topic+point+src | JSON 可解析；卡数∈[1,3]；topic/point 非空；point≠原文摘抄（长度比阈值）；src 可回溯输入 |
| read-thin 读薄 | 卡片分类分层成书 | 卡片数≥1；每卡有 topic | 书数组 2~6 本，每书 3~8 二级主题，每主题挂卡 | JSON 可解析；书数/主题数在界内；**每张输入卡都被某书收编**（无卡流失）；书间主题不重复 |
| learn 学透 | 从卡片出学习卡 | 书结构完整 | 每书 ≤5 张 recall/feynman 卡 | 卡数≤上限；问题能被原文回答（关键词条检）；背面非空且非正面复读 |

**质量门禁流转规则**：`gate.check()` 通过 → 产物传下一阶段；不通过 → 进入修复重跑（把失败原因拼回上下文让模型自修），重跑次数受防循环层约束。

#### 6.2.2 防无限循环：多层防护（禁止无界重试）

```
第 1 层 · 单次门禁重试 ≤ 2 次      同一阶段 gate 不过，带失败原因重跑，最多 2 次
第 2 层 · 阶段降级                 重试耗尽仍不合格 → 降级策略（如 read-thin 失败则退回「按书聚类」确定性算法兜底，并标注「降级产物」）
第 3 层 · 任务级熔断               全任务阶段执行/重试总次数上限（如 12 次），超限任务置 error 终止，不做静默无限循环
第 4 层 · 时间与体量护栏           单次 LLM 调用超时（如 120s）；输入/产物体量超界（如卡片 >500 张）先截断再进阶段
```

任何一层触发都写入任务进度（前端 current 文案可见，如「⚠ 读薄校验未过，第 2 次自修中…」）——**防护过程对用户可见，而不是黑箱转圈**。

#### 6.2.3 五区上下文记忆法（每个 Agent 的上下文构成）

> 每个阶段 Agent 的上下文只由五个区构成，不多不少——区外内容一律不进 prompt，防止上下文膨胀与跨阶段串味。

| 区 | 内容 | 来源 |
|---|---|---|
| ① 目标区 | 本阶段 goal + 出参标准 + 验证要点（「你要产出什么、怎样算合格」） | HarnessSpec |
| ② 输入区 | 上游产物（裁剪后）+ 素材摘录 | 编排器传递 |
| ③ 规则区 | EXTRACT 技能 + PREFERENCE 偏好（拼装好的提示词附录） | AgentSkill 装配 |
| ④ 工作区 | 本次运行中的中间推理/失败原因/自修提示（重跑时才有） | 运行时 |
| ⑤ 产物区 | 本次最终输出 + 门禁校验结果 | 阶段产物 |

#### 6.2.4 执行即销毁（无状态运行）

- 阶段 Agent 是**一次性实例**：run() 结束（产物过门禁或降级）即销毁，工作区④清空，不跨阶段、不跨运行保留任何对话状态——下一次运行从零装配五区，杜绝上次的失败上下文污染本次产出。
- 可持久的只有两类东西：**落盘的产物**（md/卡片/书）与**沉淀的技能**（AgentSkill/AgentFeedback）——「状态在库不在会话」。
- 落地约束：LlmHarnessAgent 内部每次 `agent.chat()` 新建临时会话对象，不注入 ConversationMemory；编排器持有的是 HarnessSpec 与产物，不是 Agent 实例。

#### 6.2.5 运行中偏好捕获 → 喵的专属技能

- 阶段运行中获得的用户偏好（反馈、修改后的产物 diff、门禁修复方向）即时写 AgentFeedback（带 stage + skillCodes 归因）。
- 喵周期性消化反馈，生成**按猫归属**的 PREFERENCE skill（「小肥的专属技能」，source=miaomiao）——同一只喵越用越懂它的主人，不同喵的技能池互相独立。
- 消化规则与防污染约束见 6.3。

### 6.3 Skill 装配与偏好闭环（四步循环）

```
① 装配   阶段运行前：按猫拉 enabled 且适用本阶段的 AgentSkill
         EXTRACT 规则 → 拼进 system prompt（「提炼时遵守这些规则」）
         PREFERENCE   → 拼成「主人偏好」段（「主人喜欢简洁的分点/喜欢技术细节优先」）
② 执行   HarnessAgent.run() → 产物；本次用到的 skill codes 记入任务
③ 反馈   主人对产物做处理（采纳/修改/重新生成/忽略）
         → AgentFeedback(action, stage, skillCodes, finalValue)，consumed=false
④ 消化   喵周期性把未消化反馈总结成新 PREFERENCE skill（source=miaomiao）
         → 下次装配自动生效；skill 的 usageCount 归因价值
```

**落地改动（数据层）**：
- `AgentSkill` 加 `stage` 列（`ALL / EXTRACT / READ_DEEP / READ_THIN / LEARN`）——skill 适用阶段
- `AgentFeedback` 加 `stage` 列——反馈归因到阶段
- 预置技能扩展：每阶段 2~3 条种子 EXTRACT（如 read-deep 的「卡片必须含可操作结论」、learn 的「问题必须能被原文回答」）

**偏好消化防污染**（错误偏好一旦写入提示词会持续污染后续所有产出，形成正反馈循环）：
- 每猫 PREFERENCE 技能上限 20 条，同类偏好去重；喵总结新偏好时必须给出对应的反馈证据（引用具体 feedback），无证据不入库
- PREFERENCE 全部允许用户在技能弹窗里删除/停用——主人永远是偏好的最终裁决者
- usageCount 连续 20 次装配却从未被归因到好评的偏好，喵主动提示下线

### 6.4 用户界面呈现

- **技能徽标归因**：每个阶段产物卡上显示本次使用的 Skill 徽标（如「⚡ 简洁分点」「🎯 技术优先」），hover 看技能内容——让「提炼为什么变成这样」可解释。
- **反馈即教学**：产物卡上的「👍 采纳 / ✏️ 修改 / 🔄 重新生成」就是反馈入口——主人每次处理都在教喵，不需要专门的「设置偏好」页。
- **门禁与防护可视化**：任务进度文案实时反映契约执行（「✅ 读厚产物 57 卡，校验通过」/「⚠ 读薄校验未过，第 2 次自修中…」/「🛟 已降级兜底」）——每个节点「目标→验证→通过」的完整过程对主人可见（对应 6.2.1/6.2.2）。
- **技能弹窗按阶段分组**（沿用现有技能管理弹窗，加 stage 分组页签），PREFERENCE 类标注来源（喵总结的 / 主人手写的），喵的专属技能带专属标识（对应 6.2.5）。

### 6.5 设计原则

1. **管道不动，节点可换**：工作流骨架（抓取→读厚→读薄→学透）是稳定的，每阶段的执行体、模型、提示词、技能都是可嵌入替换的。
2. **提示词是资产不是代码**：提炼规则的迭代走 AgentSkill 表（git 版本化随库走），不走代码发布。
3. **每次处理都是训练**：主人不写偏好设置，只用日常的「采纳/修改」动作教喵——偏好从行为中沉淀。
4. **归因可见**：任何一次提炼都能回答「用了哪些技能、哪条偏好影响了它」。

## 七、客观评估：设计风险与对策

> 本节是对整体设计的冷静评估——理念层成立，风险集中在「学习端的执行负担」与「AI 自治产出的质量漂移」，对策已内嵌进上文各节。

| # | 风险 | 严重度 | 对策（落点） |
|---|---|---|---|
| 1 | **学习负担反噬**：知识爆炸用户恰恰没时间；到期卡堆积会把「学习卡片」变成新的焦虑源，产品死于「复习不动」——与稍后读死于「读不动」同构 | 高 | 每书出卡 ≤5 张、每日到期 ≤10 张封顶、自动降频/休眠、「今日 3 分钟」轻入口（3.2a） |
| 2 | **苏格拉底模式摩擦力大**：被连环追问是高认知负荷交互，多数用户会逃避，做成主打功能会带来预期落差 | 中 | 定位为可选深度模式、不做默认路径、不作为主打卖点（3.2b） |
| 3 | **过早抽象**：现在只有 4 个阶段、2 种执行体，P0 就建完整 Java 接口体系是为想象中的灵活性付复杂度 | 中 | P0 落声明式契约四件套（HarnessSpec + 门禁，数据驱动、不建类层次），Java 接口在 P1 第二个实现出现时再抽（6.2.1） |
| 4 | **偏好污染循环**：喵从反馈总结的偏好若质量差，会持续污染提示词，且每次产出又强化错误偏好 | 中 | PREFERENCE 上限 20 条 + 去重 + 证据引用 + 用户可删 + 低效偏好自动提示下线（6.3） |
| 5 | **Token 成本失控感**：逐篇精读已 N 次调用，学透再叠加，一篇内容全链路 4+ 次调用，用户对成本无感知会产生不信任 | 低 | 阶段调用 Token 成本随任务进度展示（复用 TokenUsage），P2 落地（P2） |

**结论**：理念层（读厚→读薄→学透 + 引力波隐喻 + HarnessAgent 可嵌入）是成立的、有差异化的；执行层把风险 1 和 4 当头号敌人盯住——前者决定用户留不留，后者决定 AI 产出的信任度。两条都有明确对策且不增加架构复杂度。

## 八、验证标准（怎样算「真正解决问题」）

1. 一条公众号文章从粘贴到进入书里 ≤ 3 步操作，全程无需离开「喵藏」。
2. 用户一周后仍能通过学习卡片答出当初读过的核心观点（主动回忆成立）。
3. 每张学习卡片都能追溯到：哪本书 → 哪张理解卡片 → 哪篇原文（厚薄互链成立）。
4. 苏格拉底会话结束时用户明确知道「我哪里懂了、哪里还不懂」。
5. 用户每周主动打开学习卡片页 ≥ 3 次（对抗「复习不动」的北极星指标——留存比覆盖率重要）。
6. 任意一次提炼都能在界面上回答「用了哪些技能、花了多少 Token」（信任建立）。
