## 总体定位

喵藏仍是「知识加工流水线」形态：采集 → 读厚 → 读薄 → 学透，这条主线（含门禁、增量、指纹）在个人知识工具里已属少见。经过两天迭代，它已经**不只是生产机器**——检索、随身通道、知识网络三块地基都长出了雏形。当前唯一还空着的是**消费端的「引力」**：让人每天愿意回来的机制。

## 已经站稳的（不需要补）

- **三真相分离清晰**：H2 DB 管结构化（卡片/复习/关联），md + git 管文档真身（`data/library/`，一用户一目录、一猫一工作区），任何归纳/编辑可回溯可回滚
- **LLM 不可靠性被工程手段管住**：HarnessSpec 契约门禁 + PipelineRunner 重试≤3 + 任务级 budget 熔断 + 降级兜底 + 执行即销毁
- **数据模型健康**：SM-2 复习闭环（remember×ease / 连忘降级 / 休眠）、章节数（书→章→节→卡）、双链 related、文章指纹增量、AgentFeedback→Skill 偏好回流
- **增量归纳**：新文章/有修改文章自动判定，旧书不重建，主人确认清单可控；每小时巡逻 + 自动整理可关

## 缺失与短板（按严重度排序）

### 1. 复习闭环仍然完全没有「引力」
`LearnController` 只有 `today`（今日到期）和 `review`（自评 SM-2）两个接口——**没有提醒、没有连续打卡、没有留存率、没有遗忘曲线可视化**。三真相里的「复习调度记录」已经攒着，但主人看不到它的价值。wiki 的「日常栖息地」属性依旧没建立。
- 最小版本：侧栏「今日待复 N」红点 + 浏览器通知
- 完整版：复习统计卡（连续天数 / 留存率 / 未来 7 天到期曲线）

### 2. 中文高频知识源通道太窄
采集入口只有 url / text / file（`CollectController`）。公众号文章、RSS 订阅、微信读书划线这类最高频的中文输入源没有专用通道，「引力波」的引力仍全靠手动贴。

### 3. 双链可视化断在知识点层
图谱现在是 origin 文件树（Cat → 目录 → 文件），知识点之间的 `related` 关系**存了但没呈现**：没有知识点层级图，也没有反向链接视图。「把书读厚」的成果恰恰藏在这一层。

### 4. 消费端导出能力弱
`export.js` 只支持 Markdown 打包 zip。一本书不能导出单文件 HTML/PDF，学习卡不能导出 Anki 卡组——数据是自己的，但消费形态被锁在 Markdown。

### 5. 抽检机制只到「提取采纳」层
门禁校验「有没有、格式对不对」，不校验「对不对」。PREFERENCE skill 目前只从提取采纳/忽略回流，**没有随机抽样理解卡 / 学习卡让主人打分**的环节——与 HarnessAgent 理念同构，但尚未落到复习/抽检。

### 6. 数据安全未闭环：无自动化、无异地
`backup` 是手动命令、只留本地 7 份、H2 未进任何版本库。文件损坏 + 机器故障仍是单点。
- 需要：定时备份（LaunchAgent）+ H2 dump 进 git（或独立备份仓库）+ 远端推送

### 7. 新增架构债
拆分后 `static/app.js`（247KB）与 `static/app.js.bak-20260921` 已成**孤儿文件**（`index.html` 已不加载），是残骸；`?v=` 版本号靠人肉 bump，已多次因漏 bump 造成「改了没生效」的假象。
